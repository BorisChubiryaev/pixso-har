# pixso-har

Достаёт макет Pixso из `.har`-файла браузера и превращает его в компактное текстовое описание для LLM (ГигаКод, Claude Code и т.п.). Нужен на случай, когда Pixso MCP не работает.

## Как это устроено

Веб-клиент Pixso получает весь файл макета одним бинарным сообщением по WebSocket `/ws/coop`. Это формат `pixso-kw`: Kiwi-сообщение `PixsoMsg`, сжатое zstd. Схема Kiwi лежит в `/app/pixso.binary`. Обе части попадают в HAR, и скрипт:

1. раскодирует документ, получая все узлы файла;
2. находит фрейм из ссылки (`item-id=…`);
3. раскрывает инстансы компонентов с учётом переопределений: тексты, цвета, видимость, подмены, component properties;
4. пишет дерево слоёв в CSS-подобной нотации: размеры, auto-layout → flex, отступы, цвета и стили/токены, шрифты, тексты.

## Как снять HAR

1. Открыть нужный фрейм в Chrome по ссылке вида `…/app/design/<file>?item-id=185:274028`.
2. DevTools (F12) → Network → поставить галочку **Preserve log**.
3. Перезагрузить страницу (Ctrl+R) и дождаться, пока макет отрисуется.
4. ПКМ по списку запросов → **Save all as HAR with content**.

> ⚠️ В HAR есть cookies и токены сессии. Не выкладывайте его в публичные места.

## Запуск

```bash
pip install zstandard        # единственная зависимость (или утилита zstd в PATH)

python3 pixso_extract.py pixso.har                   # фрейм из item-id в ссылке
python3 pixso_extract.py pixso.har --list            # все страницы и фреймы файла
python3 pixso_extract.py pixso.har --node 182:5000   # любой другой фрейм из того же HAR
```

В одном HAR лежит **весь файл**, так что можно выгружать любые фреймы через `--node`, не снимая HAR заново.

Результат появится в `out/`:

- `<node>.md` — описание для ГигаКода;
- `<node>.json` — то же в структурированном виде;
- `images/` — картинки, если браузер их загрузил.

Опции: `--depth N` задаёт глубину раскрытия вложенных компонентов, `--hidden` включает скрытые слои, `--ids` добавляет id узлов.

## Промпт для ГигаКода

```
Сверстай экран по описанию макета из файла out/185-274028.md.
- Структуру и отступы бери из flex-row/flex-column, gap и pad.
- Цвета и шрифты бери точно из описания. Если указан [стиль], используй токен
  дизайн-системы с этим именем, если он есть в проекте.
- «⟶ компонент «…»» — это компонент дизайн-системы. Если в проекте есть
  соответствующий компонент, используй его, а не верстай с нуля.
- Координаты @(x,y) нужны только для элементов без auto-layout и с пометкой absolute.
```

## Ограничения

- Векторные иконки не экспортируются: в описании видно только, какой это компонент иконки, например «24 / Arrows / DisclosureDownOutline».
- Переменные (colorVar) показываются уже вычисленным цветом, без имени переменной.
- Формат проверен на Pixso с `schema v9.99` (клиент v3.0.0.9).
